## 採用時の補正と確認

採用時には、JSON Pointerの形式、CookieとCSRFのAND条件、OriginとRefererの優先順位・欠落時の扱い、セッションの期限、他社員が編集する場合の404、差戻しの処理順序を補正しました。適用できなかった一覧の差分は、パスのエスケープを直し、Qwenが返した修正文を使いました。

変更箇所と理由は[adoption.json](adoption.json)に記録しています。これらはCIのモデル応答を上書きして成功扱いにしたものではなく、採用版に加えた別の変更です。[review.json](review.json)には、対象ソースのハッシュと文書データ、元のモデルが選んだ根拠を残しています。

追加補正後、[68件のHTTP検査](local-checks.json)が通りました。正常系だけでなく、認証・入力エラー、他の社員の申請へのアクセス、差戻し・再申請、二重承認、承認後の変更拒否、履歴、ログアウト後の旧Cookieの無効化を確認しています。文章の全ての解釈、全入力境界、長期運用、負荷、TLSを保証する検査ではありません。

文書はレビュー用ブランチに追加しています。CIの生成結果を自動でmainへコミットする構成ではなく、採用版を確認して署名付きコミットで反映する工程があります。CIと再実行の設定は[生成・検証の手順](../api-document-generation.md)を参照してください。
